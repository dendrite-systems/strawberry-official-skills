# Getting Started with Recruiting in Strawberry

Help the user start with one real hiring decision and one reviewable result. Recruiting work should preserve job-related evidence and human ownership from role definition through pipeline follow-through.

## Choose no more than three starting points

Recommend only the routes that fit the user's immediate decision:

- Use `strawberry/recruiting/create-a-job-description` to define or revise the internal role profile, external JD, or both.
- Use `strawberry/recruiting/map-a-talent-market` when feasibility, titles, target employers, adjacent backgrounds, geography, compensation, or search levers are uncertain.
- Use `strawberry/recruiting/source-candidates` when the role and market are sufficiently understood and the user needs a calibrated shortlist.
- Use `strawberry/recruiting/review-applications` for an inbound application set or backlog.
- Use `strawberry/recruiting/send-candidate-outreach` for approved candidates or segments that need candidate-specific messaging.
- Use `strawberry/recruiting/prepare-candidate-interviews` before interviews.
- After an authorized interview, use Strawberry's meeting capture or another reliable record, then
  use `strawberry/recruiting/synthesize-interview-feedback` for scorecard-based synthesis.
- Use `strawberry/recruiting/review-recruiting-pipeline` for priorities, stalled candidates, evidence gaps, candidate-experience risk, ATS corrections, or coverage against hiring goals.

For broad requests, ask about the role or roles, the decision due next, current pipeline state, source systems, and approval boundaries only when the answer changes the route. Do not force a full setup before useful work.

## Start bounded and reviewable

Use existing tabs, connected apps, files, and approved memory before asking the user to repeat context. For new or subjective criteria, propose a small calibration set before scaling. Keep facts, candidate claims, inference, and unknowns distinct. Preserve source links for material claims.

Hiring recommendations require qualified human review. Job publication, outreach, interview scheduling, ATS writes, sharing, and Routines are separate approval states. Never infer permission for one from another.

## Make the accepted workflow reusable

Once a focused workflow works, offer to save its criteria, sources, fields, destination, and review points as a custom skill. Use `strawberry/operations/set-up-shared-team-workflow` when ownership and review should be shared. Offer a Routine only after the workflow is stable, has a useful trigger or cadence, and can begin read-only or draft-first.
